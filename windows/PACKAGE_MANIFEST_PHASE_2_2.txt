PHASE 2.2 CODE CHANGES
- Serialize HTTP/2 stream allocation, registration and HEADERS emission while allowing token acquisition and active streams to remain concurrent.
- Use a long stream-ID counter and disable new streams rather than allowing integer wraparound.
- Keep a started HTTP/2 frame together despite caller cancellation; bound writes to 15 seconds and abort the shared transport on failure.
- Enforce non-increasing GOAWAY last-stream IDs and stricter idle/closed-stream behavior for RST_STREAM, WINDOW_UPDATE, DATA and HEADERS.
- Validate HTTP/2 response pseudo-header ordering, lowercase/token field names, response field values, unique :status, three-digit status syntax, at most 128 fields and 64 KiB of decoded header data.
- Avoid duplicate RST_STREAM on CONNECT rejection.
- Author test source for GOAWAY monotonicity, idle stream classification, status syntax and response header validation. These tests were not run.
